# Actualizar con un cliente MCP conectado · APP-028, APP-029

Claude Desktop y otros clientes MCP mantienen `xcreenshot.exe mcp` en marcha. Windows no deja sobrescribir un programa en marcha, y el instalador se paraba con "Error opening file for writing" (Carlos, 2026-11-05).

Ahora, si `xcreenshot.exe` está en uso, el instalador lo renombra a `xcreenshot.exe.1.old` y coloca el nuevo en su lugar (`app/src-tauri/installer-hooks.nsh`):
- El cliente conserva su conexión y usa la versión nueva la próxima vez que arranque el servidor.
- La copia apartada se borra en la siguiente actualización o al desinstalar, si ya nadie la usa.
- Si el archivo está libre, no se aparta nada.

Prueba automática: `app/src/installer.test.ts` comprueba que el paquete usa el gancho y que este aparta el archivo.

Probado con un mini-instalador que incluye el gancho real, en una carpeta temporal, con `xcreenshot mcp` en marcha (2026-11-09, Windows 11):
- [x] Sin el gancho, copiar encima del programa en marcha falla: es el error original.
- [x] Si la instalación se cancela después del gancho, `xcreenshot.exe` sigue en su sitio, con la versión anterior.
- [x] Con el gancho, la versión nueva ocupa el nombre y el servidor en marcha sigue respondiendo.
- [x] Con dos clientes, uno en la copia apartada y otro en el archivo actual, se usa un segundo nombre y ninguno se corta.
- [x] Sin nada en marcha, las copias apartadas desaparecen.
