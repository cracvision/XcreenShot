# APP-032 · Seguridad de la automatización

- (Automatizadas) interruptor general y rechazo de `settings set automation.enabled false` desde el CLI: `core::tests`, `settings::tests`.
- [ ] Con la app en marcha, `netstat -ano` (Windows) o `lsof -i -P | grep xcreenshot` (macOS) no muestra ningún puerto en escucha de XcreenShot.
- [ ] Con otra cuenta de usuario con sesión abierta, `xcreenshot app ping --no-launch` de ese usuario no conecta con la instancia del primero.
- [ ] Desactiva "Permitir el control por CLI y agentes": `xcreenshot settings list` sale con 6 y nombra el ajuste; `xcreenshot app ping --json` responde con `"automationEnabled": false`.
- [ ] (M1) Una captura lanzada desde el CLI o MCP muestra la notificación de automatización.

## Resultados

- Windows 11 (26200), modo desarrollo, 2026-10-12: `Get-NetTCPConnection`/`Get-NetUDPEndpoint` no muestran puertos de XcreenShot ni de su WebView2. La tubería `\\.\pipe\xcreenshot-<usuario>-s<sesión>` tiene SDDL `O:<SID del usuario>D:P(A;;FA;;;OW)(A;;FA;;;SY)`: solo el propietario y SYSTEM. Con el CLI, `settings set automation.enabled false` sale con 6. Pendiente: prueba real con un segundo usuario; notificación de automatización (M1).
